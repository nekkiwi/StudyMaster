# Decision log

Decisions made while designing StudyMaster, with the reason and what else was
considered. Newest topics at the bottom. Change a decision by adding a new
entry, not by editing history.

| # | Decision | Why | Alternatives considered |
|---|---|---|---|
| 1 | Material is entered as **chunks** (chapter / slide deck / both) with page and slide counts | Simple to enter, enough to estimate effort | Hours per chunk (people don't know), page ranges (more typing) |
| 2 | Difficulty is a **preset weight** 0.5 / 0.8 / 1.0 / 1.2 / 1.5 | Easy choice, multiplies effort | Free number (confusing), per-chunk difficulty (too much input) |
| 3 | Everything is converted to **effort minutes**: read + summary + Anki card creation, × weight | Studying includes summaries and making cards, not just reading | Pages only; separate per-step planning |
| 4 | **Anki review is its own item category** (like chapter / slide deck), first item of every session; Anki-only sessions on free days | Daily Anki is part of the work and should be visible and checkable; reviews must never pause | A fixed block hidden inside each session (first version); no Anki planning |
| 5 | Sessions are **2–3 h blocks, 1–4 per day** (2 morning + 2 afternoon) | Matches how students plan their day | Free-form time blocks (more complex UI) |
| 6 | **Preferred vs. max sessions per day** | The plan uses the normal rhythm; more only with approval | Single number (no way to express "only if needed") |
| 7 | Main study ends **N days before each exam** (default 2) + a **short review session** right before, **reserved first** | Well in advance; back-to-back exams still get a review | Plan right up to the exam (cramming) |
| 8 | **Weekly buffer half-day = catch-up reserve**: empty by default, used only after falling behind, and only with approval | Free time in good weeks, a safety net in bad weeks | Always-protected free time (pushes catch-up straight to extra sessions) |
| 9 | **Escalation ladder**: normal → shorter exam buffer → weekly buffer → extra sessions → infeasible; everything beyond normal needs approval | Never silently overbook; smallest change first | Auto-apply everything; just show "doesn't fit" |
| 10 | **Approvals remember exact slots**; needing fewer is fine, anything new asks again | One approval shouldn't be a blank cheque | Approving a level once for good |
| 11 | **Least-slack** filling, sessions **packed** (cut pieces to fill), prefer one subject per session | Earliest/most at-risk work first; no half-empty sessions; less task switching | Earliest-deadline-first only; whole chunks only (left ~1 h unused per session) |
| 12 | **Pacing setting, default "Steady" (even)**, "Finish early" optional | Even pace = study and Anki on most days, less early cramming; falls back to ASAP when tight so it never fits less | Finish early only (left weeks empty before exams) |
| 13 | **Evening Yes/No check-in**, "No" → tick read/summary/cards per piece; ignored → asked next morning; after 2 days counts as missed | Two taps on a good day, honest data on a bad day | Only manual editing; daily time tracking (too much effort) |
| 14 | Planner is a **pure TypeScript package** with tests, shared by app, backend and AI | One source of truth, easy to test, runs anywhere | Planning logic inside the UI |
| 15 | **Local-first** web app now (localStorage + JSON backup), backend later | Ship and test the product before building accounts | Backend first |
| 16 | **React + Vite + Tailwind PWA** | Fast, one codebase for desktop and phone, installable | Native apps (two codebases), Next.js (not needed) |
| 17 | **Cloudflare** (Pages + Workers + D1 + Cron) for hosting | Free tiers, one platform, auto-deploy, cron for reminders | Vercel/Netlify (static only), Firebase (scheduled functions need paid plan), Supabase |
| 18 | Android app via **installable PWA**, later **Google Play as a Trusted Web Activity** | One codebase, updates come from the website | Native Android app; React Native |
| 19 | **Guest-first onboarding**, Google sign-in or email link, no passwords | Start in seconds; sign in only for sync/reminders | Account required up front |
| 20 | AI in three layers: **built-in assistant** (our server key) + **MCP connector** for Claude users + **copy-paste prompts** | Free and invisible for normal users; power users can use their own Claude | Requiring a Claude account; one shared Claude account (against terms, no API, privacy); asking users for API keys |
| 21 | Assistant and MCP server **share one tool set**; AI changes follow the approval rules | No drift between the two; AI can't overbook | Separate implementations |
| 22 | Host the web app as a **Cloudflare Worker with static assets** (Workers Builds from GitHub, `wrangler.jsonc`) instead of classic Pages | Cloudflare's current default flow; the planned backend can live in the same Worker | Classic Cloudflare Pages project; GitHub Actions deploy; manual deploys |
| 23 | **A chunk is a lecture: watch the recording → read → write cards** (recording minutes per chunk, default 60; video time not scaled by weight, optional speed factor). Replaces the summary step (supersedes #3) | That's how the material is actually studied; a 1-hour video takes an hour regardless of difficulty | Keep summaries; recordings as separate chunks |
| 24 | **Anki at the end of each study session**: learn the new cards written in it + review earlier cards of the same subjects; learning time is reserved with the lecture piece (supersedes the "first item" part of #4) | Matches A (lecture work) then B (study cards); new cards are learned while fresh | Anki first in every session; one daily Anki block |
| 25 | **Pieces follow the step order** (watch → read → cards), and the check-in only offers the steps planned in each piece | A piece should say concretely what to do ("🎬 60 min · 📖 12 pages"); no cards before watching | Proportional slices of every step |
| 26 | **Weekly plan instead of "sessions per day"**: per weekday, 0/1/2 sessions in the morning and afternoon. **Default: weekday afternoons + one half-day (morning) on Sat and Sun.** Free days stay free (no Anki-only, no extras). Max sessions per day still caps extras, only on study days (supersedes #5 and #6) | Students don't study every day; mornings are often lectures | Same sessions every day; days-off list only |
| 27 | **Material import = automatic detection + a review step** before anything is saved (untick, edit, merge, move, match subjects); all parsing on the device | Fast setup without trusting a guess blindly; private; no server or AI needed for the common cases (folders, bookmarked PDFs, slides, videos, pasted TOC) | AI-only import; manual entry only; uploading files to a server |
| 28 | **Anki via AnkiConnect on desktop** (permission popup, create/import decks, open exact deck), **app links on phones** (AnkiMobile study link, AnkiDroid opens the app) | The only automation Anki allows for a web app; AnkiDroid opens exact decks only for installed apps; AnkiWeb has no API | Anki account as login (impossible: no OAuth/API); native Android wrapper now (later, if needed) |
| 29 | **Login and sync with Firebase** (Google + email/password incl. reset emails; Apple later), website stays on Cloudflare (supersedes the login part of #17/#19) | Cloudflare's free plan allows ~10 ms CPU per request – too little for secure password hashing; Firebase is free, sends reset emails without our own domain, and syncs without server code | Cloudflare paid plan ($5/month) with own auth code; Google-only login |
| 30 | **Landing page = sign-in** (Google / email), using the app without an account is a small link; **sign-in syncs silently**: the account's plan wins, a device's own earlier plan is kept as a restorable backup | "Same account on phone and laptop – it's just there"; no confusing questions on first sign-in, and nothing gets lost | Asking which plan to keep (first version); merging plans automatically (duplicates) |
| 31 | **The wizard never blocks silently**: a disabled "Next" always says why; a subject without material is a hint (with "Remove") instead of a blocker; subject names are a big, obviously editable field in the import review, the wizard and the subject editor | A user got stuck after a book import created an extra subject named after the file | Requiring material for every subject |
| 32 | **Subjects and lectures link to Anki decks** (`ankiDeck` on subject and chunk). A subject can be set up by picking an Anki collection: sub-decks become its items, or are **linked to existing items by similar name** (same lecture number or shared words); links can be fixed by hand in the subject editor. ▶ Anki opens exactly the linked deck of the item studied, nothing else. **The copyable Filtered-Deck search is removed** | People already have their own deck structure ("Bio WS26::VL03 …"); forcing `Subject::Lecture` names meant ▶ Anki opened nothing useful. The search string confused users | Requiring StudyMaster's deck names; fuzzy matching on every click instead of stored links; keeping the copy button |
| 33 | **Week grid = Mon–Sun columns × Morning/Afternoon rows**, – / 1 / 2 side by side per cell, **big preset buttons above**; on phones the grid scrolls sideways with sticky row labels. **Splitting limits leave the wizard** and live in Settings ("Splitting long material") with an explanation; the UI never says "chunk" | Reads like a calendar week; presets are the common case. "Chunk" and the split limits confused a first-time user | Rows per weekday (first version); hiding the limits completely |
| 34 | **▶ Anki per device**: computer → AnkiConnect, and the first press walks through connecting (incl. the browser's "apps on this device" prompt) and then opens the deck; Mac Safari gets an explanation (use Chrome/Edge/Firefox); iPhone → AnkiMobile `study?deck=`; Android → AnkiDroid's browsable `browser?search=deck:"…"` link (exact deck's cards). Replaces the AnkiDroid launcher intent, which Chrome won't start from a web page (it showed the Play Store) | Each platform's only allowed way to reach that exact deck from a website; no dead ends without an explanation | Requiring Anki setup in onboarding; AnkiWeb fallback without explanation; native Android app now |
| 35 | **Studying stays in Anki; StudyMaster mirrors Anki's structure and numbers** from a computer with AnkiConnect: links by deck id (survive renames), real card counts per lecture deck (drive "write cards" progress and review load), due counts per subject for the next 7 days (drive Anki time in the plan), new lectures get sub-decks, new sub-decks are suggested as lectures. Numbers sync to the account, so phones use them | Planning Anki time from real numbers instead of a formula; no manual card counting; renaming decks in Anki must not break ▶ Anki | Built-in flashcards in StudyMaster (rejected: studying belongs in Anki); estimating only; reading Anki on phones (not possible from a website) |
| 36 | **Import is also inside the subject editor**, preset to add to that subject; stacked dialogs close one at a time | Adding a subject later should offer the same import as the setup wizard | Only the Subjects page Import button |
| 37 | **PDFs without bookmarks: read the printed table of contents** (first ~24 pages, "Inhalt/Contents" heading). Besides "Title … 12" lines, a **block reader** handles scanned layouts: the line repeated in every chapter marks chapters, the line(s) before it are the title, the first number of each page-number column is the start page; OCR letter-spacing is undone ("E s s e n u n d T rin k e n" → "Essen und Trinken"); a glued label ("LektionLektion…") becomes "Lektion N:" | A real German textbook (scanned, no bookmarks) came out as one item; this stays free, instant, offline and private | Sending every book to an AI (cost, privacy) – AI stays the planned fallback ("Import with AI") |
| 38 | **"Let AI read the contents"**: an optional button in the import review sends only the table-of-contents text to **Claude Haiku 5.5** via our Worker (`/api/toc`, structured output); signed-in users only (Firebase ID token verified in the Worker), 20 reads/user/hour, key as a Worker secret. The free on-device reader stays the default | Messy scans are a language task; Haiku reads them reliably for ~$0.001; the user chose Claude over free models; the button keeps it private and cheap (nothing is sent unless asked) | Free Cloudflare Workers AI (weaker on OCR text), Gemini free tier (data may be used for training), sending every import automatically |
| 39 | **AI reads are made stable**: exact-number instructions, 3 parallel reads with a per-field majority, and a per-device answer memory (hash of the text) | The same book gave slightly different chapters/pages from run to run (Haiku 5.5 doesn't allow temperature 0); 3 reads cost ~$0.003 and take no longer | Temperature 0 (not available), one read (varied), server-side cache (Cache API doesn't work on workers.dev) |
| 40 | **Plan days are colored by their subjects**: one subject = light tint, two = diagonal split, more = diagonal stripes; replaces the indigo busyness heat map | See at a glance what each day is about | Busyness-only heat map; colored dots per day |
| 41 | **AI reads tables of contents by default** (signed in); the quick on-device reader is the fallback and stays one tap away in the review. Day colors use plain rgba (not `color-mix`) and split corner to corner | The AI result is better on real scans; users asked for it as the default. `color-mix` isn't supported in older browsers, so colors didn't show for a user | AI only on request (first version) |
